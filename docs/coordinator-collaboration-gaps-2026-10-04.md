## Push model acceptance

The lead ended its first turn, then received server continuation delivery `a5def083-a55a-4b5a-80a6-2503fcb08a90` containing Orion progress and Lyra findings. This is live evidence of one successful idle-to-active push path in this app-managed room. It does not establish which message alone triggered the turn, standalone external CLI support, all-provider parity, or correct behavior under gates.

The target contract should be durable actionable events, a bounded event digest, stable obligation IDs, and one continuation scheduled when the lead becomes available. Heartbeats and usage-only telemetry should not spend model turns. Events arriving during an active turn must remain available for a later turn. Human-owned permissions/questions stay pending while unrelated agent work continues. A bounded maintenance sweep may recover delivery, but model turns should not poll for health.
